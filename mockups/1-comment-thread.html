I reproduced this against the attached script. The server closes idle sockets at 5s, but the pool's keep-alive timeout defaults to 4.9s. Under load, a request can be written to a socket the server is already closing.

Lowering keepAliveTimeout to 4s removes the failures locally (0 in 20,000 requests). A draft fix is in #4190.
